## 1. 需求来源

用户希望给 Shimeji 增加「调皮模式」，共 5 个需求点：

1. **倾向运动而非静止**：Shimeji 更活跃，减少发呆/静坐。
2. **分裂/克隆概率增加**：更容易繁殖出更多分身。
3. **积极与桌面窗口互动**：会捣乱，把用户窗口「扔出窗外」。
4. **积极与桌面图标互动**：可能会「吃掉」（或丢掉）用户桌面图标。
5. **追逐用户鼠标指针**，并尝试移走用户鼠标指针。

其中需求 3、4、5 会对用户日常工作产生影响，需要：
- 调研 **Windows / Linux / macOS 三平台兼容实现**；
- 设计**一键关闭 / 快速恢复**机制。

## 2. 现状调研（代码事实）

### 2.1 现有「运动/繁殖」机制

| 事实 | 证据 |
|---|---|
| 行为树 `behaviors.xml` 用 `Frequency` 加权随机选行为；`SitDown/LieDown` 等静止行为频率 200，`WalkAlongWorkAreaFloor` 等运动行为频率 100 | `conf/behaviors.xml:43-57` |
| 自主增殖行为：`SplitIntoTwo`（→ `Divide1`，`action/Breed`）、`PullUpShimeji`（→ `PullUpShimeji1`），频率 50，条件 `mascot.totalCount < 50` | `conf/behaviors.xml:58,98` |
| 繁殖开关 `Breeding`（默认 true），右键菜单「Disable Breeding」可关 | `Main.java:469-476`、`Breed.java:isEnabled()` |
| 托管模式下 `SplitIntoTwo`/`PullUpShimeji` 被 `GladosManagedConstraints` 逻辑层禁用 | `glados/GladosManagedConstraints.java:30-38` |

**结论 A**：需求 1、2 可通过**行为表频率调整 + 繁殖开关**实现，无需新引擎能力。但托管模式下繁殖被禁，需放开或提供「调皮模式专属繁殖」路径。

### 2.2 现有「扔窗口」机制（需求 3）

| 事实 | 证据 |
|---|---|
| `action/ThrowIE`：按 `InitialVX/InitialVY/Gravity` 抛物线把活动窗口移走 | `action/ThrowIE.java` |
| 行为 `ThrowIEFromLeft/Right`、`WalkAndThrowIEFromLeft/Right`（频率 20）触发扔窗口 | `conf/behaviors.xml:162-168` |
| 开关 `Throwing`（默认 true），右键菜单「Throwing Windows」可关 | `Main.java:493-501` |
| **Windows**：`WindowsEnvironment.moveActiveIE()` → `User32` 枚举窗口 + `MoveWindow` | `win/WindowsEnvironment.java:327-332` |
| **macOS**：`MacEnvironment.moveActiveIE()` → AXUIElement 辅助功能 API 移动前置窗口 | `mac/MacEnvironment.java:335-373` |
| **Linux**：`GenericEnvironment.moveActiveIE()` 是 **no-op**（`activeIE` 恒不可见） | `generic/GenericEnvironment.java:30-42` |

**结论 B**：需求 3 在 Win/mac 已有完整实现（仅需提高触发频率 + 纳入调皮开关）；**Linux 完全缺失**，需新增实现。

### 2.3 现有「桌面图标」机制（需求 4）

| 事实 | 证据 |
|---|---|
| 引擎**没有任何桌面图标交互代码**（grep 无 Desktop/Icon/Progman/SysListView） | 全仓检索 |
| Windows 桌面图标宿主：`Progman`/`SysListView32` 控件，图标是 `LVM_*` 列表项 | 平台知识 |
| macOS 桌面图标：Finder 的 `NSDesktopIconController`，无公开 API 移动单个图标 | 平台知识 |
| Linux 桌面图标：随 DE 而异（GNOME 桌面图标扩展 / KDE Plasma 桌面），无统一 API | 平台知识 |

**结论 C**：需求 4 是**全新能力**，三平台都无现成代码，且平台差异最大、风险最高。

### 2.4 现有「鼠标控制」机制（需求 5）

| 事实 | 证据 |
|---|---|
| 引擎只**读取**鼠标位置（`Environment.getCursorPos()` → `MouseInfo`） | `environment/Environment.java:95-99` |
| **没有任何写鼠标的代码**（无 `Robot.mouseMove`） | 全仓检索 |
| Java 标准库 `java.awt.Robot` 支持 `mouseMove`，三平台通用 | 平台知识 |

**结论 D**：需求 5 需新增 `Robot` 鼠标控制；三平台 API 一致，但 macOS 需要辅助功能授权、Linux 需要 X11/Wayland 会话支持。

### 2.5 现有「一键关闭/恢复」机制

| 事实 | 证据 |
|---|---|
| 右键菜单已有独立开关：`Breeding`、`Throwing`、`Sounds`（`JCheckBoxMenuItem`） | `Main.java:468-529` |
| 开关写入 `settings.properties`（`properties.store`） | `Main.java:483-489` |
| 托管模式（GLaDOS）下右键菜单被禁用 → 开关入口消失 | `Mascot.java:245-252` |
| 托盘菜单（`createTrayIcon`）在托管模式也被跳过 | `Main.java:run()` |

**结论 E**：现有开关是「单项、非托管模式」的；**没有「调皮模式」总开关**，且**托管模式下没有设置入口**（需走 GLaDOS 桥）。

## 3. 三平台能力矩阵与实现方案

### 3.1 需求 3：扔窗口

| 平台 | 现状 | 实现方案 | 风险 |
|---|---|---|---|
| Windows | ✅ 已有 `User32.MoveWindow` | 直接复用；提高频率；纳入调皮开关 | 低 |
| macOS | ✅ 已有 `AXUIElement` | 直接复用；需**辅助功能授权**（`AXIsProcessTrusted`）；提高频率 | 中（授权门槛） |
| Linux | ❌ no-op | **✅ 决策：不做**（2026-11-26 拍板）。`/status` 上报 `throwWindow: "unsupported"`，Linux 下需求 3 自动禁用，其余需求照常 | — |

**决策**：需求 3 仅 Windows + macOS（复用现有 `ThrowIE` 链路）；Linux 不实现（X11/Wayland 方案均放弃，省去 Xlib JNA 绑定与多发行版测试成本）。

### 3.2 需求 4：桌面图标

| 平台 | 现状 | 实现方案 | 风险 |
|---|---|---|---|
| Windows | ❌ 无 | 枚举 `Progman`/`SysListView32` 的 `LVM_GETITEMCOUNT`/`LVM_GETITEMPOSITION`/`LVM_SETITEMPOSITION`（JNA 调 `User32`+`ComCtl32`）；「吃掉」= 隐藏图标（`LVM_SETITEMPOSITION` 移到屏幕外或 `ShowWindow` 隐藏宿主） | 高（控件结构随 Win11 变化；需管理员？不需要，但需 UIAccess？） |
| macOS | ❌ 无 | **无公开 API** 移动 Finder 桌面图标；替代：① AppleScript `tell application "Finder"` 不支持移动图标；② 用 CGEvent 模拟拖拽（脆弱）；③ **降级为「视觉吃掉」**：图标本身不动，Shimeji 播「吃掉」动画 + 显示气泡"我吃了你的图标~"（纯表现） | 高（无 API，只能模拟或降级） |
| Linux | ❌ 无 | 随 DE：GNOME 桌面图标是 Nautilus 扩展（DBus 无移动接口）；KDE Plasma 桌面 `org.kde.plasmashell` DBus 部分支持；**无统一方案** | 高（碎片化） |

**推荐**：三平台统一采用「**表现级吃掉 + 平台尽力实现**」：
- **表现级（三平台通用）**：Shimeji 播「吃掉」动画（新增动作），气泡提示"吃掉"了哪个图标，**实际不动图标**——零风险，满足"调皮"的视觉诉求；
- **平台增强（仅 Windows 首期）**：真移动图标（`LVM_SETITEMPOSITION` 随机打乱 + 可恢复）；mac/Linux 本期只做表现级；
- **恢复**：Windows 记录原位置，关闭调皮模式时 `LVM_SETITEMPOSITION` 还原。

### 3.3 需求 5：移鼠标

| 平台 | 现状 | 实现方案 | 风险 |
|---|---|---|---|
| Windows | ❌ 无 | `java.awt.Robot.mouseMove`（标准库） | 低 |
| macOS | ❌ 无 | `Robot.mouseMove`；需辅助功能授权（与需求 3 同一授权） | 中（授权） |
| Linux | ❌ 无 | `Robot.mouseMove`；X11 可用；**Wayland 下 `Robot` 可能被合成器限制**（部分合成器允许，部分不允许） | 中（Wayland 差异） |

**✅ 决策（2026-11-26）**：统一用 `Robot.mouseMove`；「移走鼠标」实现为**把指针移到屏幕角落/随机位置**（模拟"被 Shimeji 推走"）。**独立开关 `Mischief.PushCursorEnabled`，默认关闭**——即使调皮模式开启，移鼠标也需用户单独勾选才生效。不可用时自动降级（检测：移动后读回位置无变化 → 判定 unsupported）。

### 3.4 三平台汇总（✅ 决策后）

| 需求 | Windows | macOS | Linux |
|---|---|---|---|
| 1. 倾向运动 | ✅ 行为表 | ✅ 行为表 | ✅ 行为表 |
| 2. 繁殖增加 | ✅ 频率+开关 | ✅ 频率+开关 | ✅ 频率+开关 |
| 3. 扔窗口 | ✅ 已有 ThrowIE | ✅ 已有(需辅助功能授权) | ❌ **不做**，上报 unsupported |
| 4. 吃图标 | 🆕 真移动+表现级 | ⚠️ 仅表现级 | ⚠️ 仅表现级 |
| 5. 移鼠标 | 🆕 Robot（独立开关默认关） | 🆕 Robot(授权，独立开关默认关) | 🆕 Robot（独立开关默认关） |

## 4. 功能需求

### 4.1 FR-1 调皮模式总开关

- **FR-1.1** 新增全局开关 `MischiefMode`（默认 **false**，settings.properties 可配 `MischiefMode`）。
- **FR-1.2** 开关入口：
  - 非托管模式：右键菜单新增「调皮模式」勾选项（`JCheckBoxMenuItem`），与 Breeding/Throwing 并列；
  - 托管模式：GLaDOS 桥新增命令 `setMischief`（`{ "cmd":"setMischief", "enabled":true }`），并纳入 `/status` 返回。
- **FR-1.3** 开启调皮模式时，自动联动开启 `Throwing`、`Breeding`；关闭时**恢复用户原设置**（记录进入前的值，退出时还原，而不是简单置 false——避免覆盖用户手动开的 Throwing）。
- **FR-1.4** 总开关是「一键关闭」的入口：任何时刻关掉 `MischiefMode`，需求 3/4/5 立即停止（需求 1/2 回到原频率）。

### 4.2 FR-2 需求 1：倾向运动

- **FR-2.1** 新增行为表覆盖 `mischief-behaviors.xml`（仿 `glados-behaviors.xml` 机制），调皮模式下加载：
  - 降低静止行为频率：`SitDown` 200→50、`LieDown` 200→40、`SitWhileDanglingLegs` 100→30；
  - 提高运动行为频率：`WalkAlongWorkAreaFloor` 100→300、`RunAlongWorkAreaFloor` 100→200、`JumpFromBottomOfIE` 50→150；
  - 提高交互行为频率：`ThrowIEFromLeft/Right` 20→120、`WalkAndThrowIEFromLeft/Right` 20→100。
- **FR-2.2** 实现方式：不修改 `behaviors.xml`，新增 `mischief-behaviors.xml`（只含 BehaviorList，Frequency 覆盖），调皮模式开启时 `Configuration.loadMischiefBehaviors()` 合并（同名行为后者覆盖频率）。
- **FR-2.3** 关闭调皮模式 → 重新加载原 `behaviors.xml`（`Main.reloadConfigurations()` 已有此能力）。

### 4.3 FR-3 需求 2：分裂/克隆概率增加

- **FR-3.1** 调皮模式下 `SplitIntoTwo`/`PullUpShimeji` 频率 50→200。
- **FR-3.2** 托管模式：`GladosManagedConstraints` 增加「调皮模式放行」——`MischiefMode=true` 时允许这两个行为（但仍受 `maxInstances` 上限约束，见克隆需求文档）。
- **FR-3.3** 非托管模式：`Breeding` 开关保持有效；调皮模式开启时自动置 true（FR-1.3 联动）。

### 4.4 FR-4 需求 3：扔窗口（✅ 决策：仅 Windows/macOS）

- **FR-4.1** Windows/macOS：复用现有 `ThrowIE` 链路，仅靠行为表频率提升触发（FR-2.1 已含）。
- **FR-4.2** **Linux 不实现**（决策）：`GenericEnvironment` 保持 no-op；`/status` 上报 `throwWindow: "unsupported"`，Linux 下需求 3 自动禁用，其余需求照常。
- **FR-4.3** macOS 授权：未获辅助功能授权时 `moveActiveIE` 无效 → 检测失败后上报 `throwWindow: "unsupported"` 并降级。
- **FR-4.4** 扔窗口温和强度（决策）：`Mischief.ThrowDistance`（默认 300px）、`Mischief.ThrowFrequency`（默认每 **30s** 至多 1 次）。

### 4.5 FR-5 需求 4：吃图标（✅ 决策：表现级 + Windows 真移动）

- **FR-5.1** 新增动作 `EatIcon`（动画：Shimeji 凑近桌面图标→张嘴→吞下→满足脸）。
- **FR-5.2** 触发：调皮模式下，Shimeji 走到桌面图标所在区域时按概率触发。
- **FR-5.3** **表现级（三平台通用）**：播动画 + 气泡「吃掉」了 `<图标名>`，**图标实际不动**——零风险，满足"调皮"视觉诉求。
- **FR-5.4** **Windows 增强（决策采纳）**：真移动图标（`LVM_GETITEMPOSITION` 记录原位置 → `LVM_SETITEMPOSITION` 移到随机位置），记录原位置表，关闭调皮模式时还原；控件结构探测失败（Win11 结构变化）→ 自动降级表现级。
- **FR-5.5** **macOS/Linux 仅表现级**（决策）：无公开 API 移动桌面图标，不实现真移动。
- **FR-5.6** 图标坐标获取：
  - Windows：`LVM_GETITEMPOSITION` 枚举 `SysListView32`；
  - mac/Linux：不取真实坐标，Shimeji 在屏幕底部随机触发「吃图标」动画（表现级）。
- **FR-5.7** **安全底线**：「吃掉」= 移动或表现，**绝不删除**用户图标。

### 4.6 FR-6 需求 5：移鼠标（✅ 决策：独立开关，默认关闭）

- **FR-6.0** 独立开关 `Mischief.PushCursorEnabled`（**默认 false**）：即使 `MischiefMode=true`，移鼠标仍不生效，需用户在设置里单独勾选（或 GLaDOS 桥 `setMischief { pushCursor:true }`）。
- **FR-6.1** 新增动作 `PushCursor`：Shimeji 靠近鼠标 → 用 `Robot.mouseMove` 把指针移到随机方向 100~300px。
- **FR-6.2** 触发：调皮模式 + PushCursorEnabled 时，`ChaseMouse` 行为增强——追到鼠标后触发 `PushCursor` 而非只看着。
- **FR-6.3** 频率限制（温和）：`Mischief.PushCursorInterval`（默认每 **15s** 至多 1 次），避免鼠标失控。
- **FR-6.4** 可用性检测：移动后 100ms 读回 `MouseInfo`，若位置未变 → 标记 `pushCursor: "unsupported"`，自动停止该需求。
- **FR-6.5** 授权：macOS 需辅助功能授权；未授权时 `Robot` 移动无效，走 FR-6.4 降级。

### 4.7 FR-7 一键关闭与快速恢复（✅ 决策：三入口 + 全量记录 + 崩溃自愈）

- **FR-7.1** 关闭入口（✅ 决策选中三项；**不含全局热键**）：
  - 右键菜单「调皮模式」取消勾选（非托管模式）；
  - GLaDOS 桥命令 `setMischief { enabled:false }` / `mischiefRestore`（托管模式）；
  - GLaDOS 设置页 UI 开关 + 「一键恢复」按钮（托管模式，经桥命令转发）。
- **FR-7.2** 关闭时恢复清单（按序执行）：
  1. 停止需求 3/4/5（立即，不等待当前动作播完）；
  2. 还原被移动的窗口位置（Windows 记录表）；
  3. 还原被移动的桌面图标位置（Windows）；
  4. 重新加载原 `behaviors.xml`（需求 1/2 频率还原）；
  5. 恢复进入前的 `Throwing`/`Breeding` 用户原设置（FR-1.3）。
- **FR-7.3** 恢复保证（✅ 决策：全量记录 + 崩溃自愈）：任何路径（正常关闭/崩溃/杀进程）下，**已移动的窗口与图标位置记录持久化**到 `mischief-restore.json`，下次启动时若检测到 `restored:false` 项则自动还原。
- **FR-7.4** 托管模式下 GLaDOS 退出联动：`quit` 命令前自动执行 FR-7.2 恢复。

## 5. 接口协议设计（增量）

### 5.1 GLaDOS 桥新增

```
GET /status
→ { ..., "mischief": { "enabled": false, "throwWindow": "supported"|"unsupported",
                        "eatIcon": "visual"|"real"|"unsupported",
                        "pushCursor": "supported"|"unsupported" } }

POST /control  { "cmd": "setMischief", "enabled": true, "pushCursor": false }
POST /control  { "cmd": "mischiefRestore" }   // 立即恢复（等价 FR-7.2）
```

- `setMischief.enabled`：总开关（需求 1/2/3/4 生效）。
- `setMischief.pushCursor`：需求 5 独立开关，默认 false（决策）。

## 8. 验收标准

### 8.1 功能
- [ ] 开启调皮模式后，Shimeji 明显更活跃（静止行为占比下降，可统计）。
- [ ] 分裂/克隆频率显著上升，但不超过 `maxInstances` 上限。
- [ ] Windows/macOS：Shimeji 会扔窗口（受 30s 频率限制）；**Linux 上报 `throwWindow:"unsupported"` 且不影响其他需求**。
- [ ] 吃图标：三平台播动画+气泡；Windows 真移动图标且可还原；mac/Linux 图标不动。
- [ ] 移鼠标：独立开关默认关；开启后才生效，15s 频率限制不失控；不可用时上报 unsupported。
- [ ] 一键关闭（右键菜单 / 桥命令 / GLaDOS 设置页按钮）后，5 秒内所有调皮行为停止，窗口/图标位置还原。

### 8.2 兼容与回归
- [ ] 非托管模式原版行为不受影响（MischiefMode=false 时零改动）。
- [ ] 托管模式克隆/多实例功能与调皮模式共存（上限约束优先）。
- [ ] 崩溃/杀进程后重启，未还原的窗口/图标自动还原。

### 8.3 性能
- [ ] 调皮模式下 40ms 主循环无掉帧。
- [ ] 窗口/图标位置记录不无限增长（恢复后清理）。

## 10. 决策结论（2026-11-26 已确认）

| 决策项 | 结论 | 说明 |
|---|---|---|
| **1. 扔窗口跨平台范围** | **B. 仅 Windows + macOS，Linux 不做** | 复用现有 `ThrowIE` 链路；Linux 上报 unsupported，省去 Xlib JNA 绑定与多发行版测试 |
| **2. 吃图标语义** | **B. 表现级 + Windows 真移动** | 三平台播动画+气泡；Windows 真移动+可还原；mac/Linux 图标不动；绝不删除 |
| **3. 移鼠标默认** | **B. 独立开关，默认关闭** | `Mischief.PushCursorEnabled=false`，调皮模式开启后仍需单独勾选 |
| **4. 关闭入口** | **右键菜单 + GLaDOS 桥命令 + GLaDOS 设置页 UI**（不含全局热键） | 非托管走菜单；托管走桥命令/设置页 |
| **5. 恢复策略** | **A. 全量记录 + 崩溃自愈** | `mischief-restore.json` 持久化，重启自动还原未恢复项 |
| **6. 调皮强度** | **A. 温和** | 扔窗口 30s/次、移鼠标 15s/次、繁殖上限 8 |
| **7. 本轮实施范围** | **仅细化需求文档，不进入编码** | 两份文档定稿后待后续排期 |

> 原"待确认项"已全部关闭。P2（Linux 扔窗口）已因决策取消。
